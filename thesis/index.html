Abstract

Application programming interfaces (APIs) connect mobile applications to their back-end services, yet the specifications that document them are often incomplete or outdated. This thesis presents the Automated Pipeline Test System (APTS), which infers OpenAPI Specifications (OAS) for Android applications from their network traffic at scale. Each application runs in an isolated container with an Android emulator, is exercised automatically with the Monkey UI tool, and has its HTTP(S) traffic intercepted by a man-in-the-middle proxy (mitmproxy) and recorded as HAR files. The captured traffic is cleaned by a multi-stage noise-reduction step that removes connectivity checks, static assets, and third-party analytics and telemetry; it is then segmented by base API and converted to OAS. To build a ground truth, a weighted keyword heuristic selected 259 mobile-related specifications from the APIs.guru repository, which were mapped to 9,674 APKs from AndroZoo. A five-minute screening run identified 2,073 interceptable applications, each of which was then tested for one hour across 12 parallel containers, taking about eight days in total. Three specification inference tools (har-to-openapi, mitmproxy2swagger, and RestTestGen) and four specification comparators (openapi-diff, oasdiff, api-schema-diff, and RestTestGen) were evaluated against the ground truth. mitmproxy2swagger proved the most robust inference tool, recovering about 500 unique endpoints without failures, while the comparators differed widely in stability and in the 148,833 difference records they produced. The results also reveal API drift: applications call endpoints that their published specifications do not document.
